# 프로젝트 주요 업데이트 계획

이 문서는 babapk 도전 시스템 및 zpke 신규유저 분류 기능 구현을 위한 전체 작업 절차와 내역을 정리한 문서입니다.

---

## 1. babapk 도전 시스템 구현

### 1.1 DB/엔티티 설계
- 별도의 challenge 테이블 없이, 각 랭킹별 유저 테이블(z_user, m_user, b_user)에 도전 관련 필드가 존재
  - `challenge` (string, nullable): 현재 도전 중인 상대방 닉네임
  - `challengeDate` (date, nullable): 도전 시작 날짜(3일 체크 등)
- 도전 신청/수락/포기/자동승리 등 모든 상태 관리는 이 필드를 기준으로 처리
- babapk도 b_user 테이블에 동일한 구조가 이미 구현되어 있으므로, zpke/mpk와 완전히 동일한 방식으로 도전 시스템 구현 가능

### 1.2 백엔드 API
- 도전 생성(POST), 도전 목록 조회(GET), 도전 응답/결과 처리(PATCH/POST)
- 3일 내 미응답 자동 패배 처리(스케줄러/배치 또는 요청시 체크)

### 1.3 프론트엔드 UI
- babapk 랭킹 페이지에 "도전하기" 버튼 추가(상위 랭커 대상)
- 내 도전/받은 도전 목록, 응답/경기 결과 표시
- 알림/경고 메시지(미응답 시 패배 등)

### 1.4 공통/기타
- 기존 zpke/mpk 도전 시스템 참고(구현 코드/DB 구조 등)
- 어드민 페이지에서 도전 현황 관리(필요시)

## [보강] babapk 도전 시스템 설계 (zpke/mpk 구조 참고)

### 1. 전체 구조 개요
- zpke/mpk 도전 시스템과 동일한 구조로 babapk 도전 시스템을 설계
- 랭킹페이지에서 상위 랭커에게만 '도전하기' 버튼 노출, 도전 신청 가능
- 내정보(마이페이지)에서 도전 현황 확인, 도전 취소/자동승리 처리 가능
- 받은 도전은 별도 폼에서 경기/포기(수락/거절) 처리

### 2. 프론트엔드
- **rank.svelte**
  - babapk 모드에도 상위 랭커에게 '도전하기' 버튼 노출
  - 버튼 클릭 시 도전 신청 API 호출
  - 하단에 '도전승인(My challengers)' 버튼 → 도전 관리 폼 진입
- **form/myinfo.svelte**
  - babapk 모드에도 내 도전 현황(도전 상대, 날짜 등) 표시
  - '도전 취소', '자동 승리' 버튼 제공
- **form/challenge.svelte**
  - babapk 모드에도 받은 도전 목록, '경기(Play)', '포기(Give Up)' 버튼 제공

### 3. 백엔드 API
- `/rank/challenge/babapk/show` : 도전 목록 조회(POST)
- `/userdata/challenge/cancel` : 도전 취소(DELETE)
- `/record/challenge/win` : 도전 수락/경기 결과 입력(POST)
- `/record/challenge/lose` : 도전 포기/패배 처리(POST)
- `/record/challenge/check` : 도전 자동승리(응답 기간 경과 시) 체크(POST)
- (기존 zpke/mpk와 동일한 API 구조, mode 파라미터만 babapk로 구분)

### 4. DB/엔티티
- 기존 zpke/mpk 도전 테이블 구조 참고, `babapk_challenge` 테이블 신규 생성
  - id, challenger(도전자), defender(수비자), status(대기/수락/거절/미응답), created_at, updated_at 등
- 도전 상태/결과/응답일시 등 관리

### 5. 기타 구현 포인트
- 도전 신청/수락/포기/자동패배 등 모든 로직을 기존과 동일하게 babapk에 맞게 구현
- 기존 zpke/mpk 도전 시스템의 코드/로직/DB를 최대한 재사용
- 어드민 페이지에서 도전 현황 관리(필요시)

### 6. 예상 작업 순서

이 설계는 기존 zpke/mpk 도전 시스템의 구조와 흐름을 최대한 일치시키는 것을 목표로 하며, babapk 특성에 맞는 세부 조정만 추가로 반영하면 됩니다.

이 문서는 향후 업데이트 작업의 기준이 되는 절차/내역을 정리한 것이며, 실제 개발 진행에 따라 세부 내용이 추가/수정될 수 있습니다. 

### [보강] 실제 코드 구조 기반 작업 계획

#### 프론트엔드
- rank.svelte, myinfo.svelte 등에서 `{#if $mode != "babapk"}` 조건을 제거하거나 수정하여, babapk 모드에서도 도전 관련 UI(도전하기 버튼, 도전 현황, 도전 취소/자동승리 등)가 노출되도록 변경
- 기존 zpke/mpk와 동일하게 babapk 모드에서도 도전 기능이 동작하도록 UI 활성화

#### 백엔드
- 대부분의 도전 관련 API/서비스가 이미 mode === "babapk" 분기를 지원하므로, 프론트 활성화만으로 정상 동작 가능
- 누락된 분기/로직이 있다면 추가 구현
- 전체적으로 기존 zpke/mpk 도전 시스템과 동일한 방식으로 babapk 도전 시스템 구현
